# 财报解读

## 目标与边界

以财务报告分析为中心，用公告原文、附注、审计意见和财务数据还原本期财务变化及其会计与经营原因。结论必须先于数据，数据只作为判断证据；不得把报告改写成指标罗列，不得用管理层叙事替代会计证据。

公司业务和经营模式只用于解释收入确认、成本结构、资产周转、现金流及风险科目，不扩展为公司基本面全景、行业前景、竞争优势、估值或投资建议。

核心问题：

1. 本期三表和关键财务指标发生了哪些实质变化，变化由哪些科目驱动？
2. 收入和利润增长来自经常经营、结构变化、并购扩表，还是一次性项目或会计处理？
3. 利润能否转化为现金，资产能否回收，债务、流动性和资本约束是否安全？
4. 成本与研发投入是否有效，附注和审计意见揭示了哪些报表风险？

## 数据依赖与参考路由

- 公告列表与原文：`hedgehog-news-reports`
- 公司代码、三表、财务指标、审计意见、主营构成：`hedgehog-company-index-data`

每次分析都先读 [会计口径、附注与证据规则](references/accounting-and-calculation.md) 和 [输出规范](references/output-template.md)。确定 `comp_type` 后只读匹配的公司类型策略：

| comp_type | 公司类型 | 必读策略 |
|---|---|---|
| `1` | 一般工商业 | [一般工商业](references/general-industrial.md) |
| `2` | 银行 | [银行](references/bank.md) |
| `3` | 保险 | [保险](references/insurance.md) |
| `4` | 证券/券商 | [证券](references/securities.md) |

财务字段和接口参数以两个依赖 skill 的当前文档为准；分析阈值可参考 `hedgehog-company-index-data/references/fin-analysis-guide.md`，但阈值只是行业启发，不是机械评级标准。

## 工作流

### 1. 锁定公司与公司类型

1. 用户只给简称或公司名时，先调用 `getStockBasic(stock_name=...)` 核实带交易所后缀的 `stock_code`，禁止猜代码。
2. 用最新一期 `queryIncome` 的 `comp_type` 确认公司类型；与业务实质冲突时说明原因，并以法定报表类型选择三表明细字段。
3. 一般工商业还要根据主营构成、资产结构和现金周转，选择重资产周期、分销高周转、品牌消费、轻资产科技、项目合同或混合财务模式。该分类只用于选择报表分析重点，不延伸为完整基本面研究。

### 2. 找到最新完整定期报告

1. 调用 `queryAnnouncementList(stock_code=[代码], announce_type='U1', sort='announcement_date', limit=20)`。为避免 30 天窗口漏掉最近财报，默认不传 `start_date`。
2. 从候选中选择报告期最新的完整年度报告、半年度报告或季度报告。排除报告摘要、英文版、提示性公告、审阅/鉴证报告等非完整正文；同一报告期有修订稿或更正稿时使用发布时间最新的完整修订稿，并记录修订事项。
3. 调用 `getAnnouncementDetail(announcement_id=...)` 获取 `content_md`、`url` 和解析状态。公告列表的摘要和自动解读只能用于定位，不能替代原文与附注。
4. 若 `content_md` 缺失或 `parse_skip_reason` 非空，使用可用的 PDF/网页读取能力访问 `url`。仍无法读取时继续完成可验证的数据分析，但必须显著标注“附注未完成核查”、降低结论置信度，不得声称已完成深度财报核验。

### 3. 确定本次重点报告期

1. 从最新完整官方定期报告的标题和正文确定 `P_report`。默认重点报告期 `P_target = P_report`，公告原文及附注是本次解读的主对象。
2. 分别查询 `queryIncome`、`queryBalanceSheet`、`queryCashFlow`、`queryFinanceIndicator` 的最新 `end_date`，记录各接口更新进度；不要为了求交集而自动把 `P_target` 降到更早报告期。
3. 若接口报告期晚于 `P_report`，先按该报告期重新检索 U1 公告，排除公告漏检；找不到完整官方报告时，不把仅由接口出现的季度设为主分析期。
4. 若接口报告期早于 `P_report`，仍以 `P_report` 为主，从报告原文取得最新三表和附注，接口数据只补充历史序列并明确更新滞后。只有最新报告正文无法读取、最新三表也无法可靠取得时，才退回最近一个资料完整的报告期，并显著说明分析并非覆盖最新一期。
5. 财务指标接口是补充而非主报告期成立的必要条件；指标缺失时可用同口径三表计算，无法计算则留白。
6. 用户指定历史截止日时，不得使用该日之后发布的公告或数据。
7. 明确报告类型、合并口径、币种、单位、是否审计及比较口径。默认优先合并报表 `report_type=1`；有追溯调整时使用报告中重述后的可比数，并说明调整影响。

### 4. 收集最小充分证据

围绕已经提出的问题取数，不预先倾倒全部字段：

- 目标期与上年同期：一般工商业取收入、营业成本、归母净利润、扣非净利润、经营现金流、自由现金流及关键利润率；银行、保险、证券改取类型策略规定的盈利驱动、风险资产、资本和监管指标。
- 最近 4–8 个报告期：判断边际变化和季节性；需要检验财务趋势稳定性时扩展至 3–5 个完整年度。
- 资产负债表：目标期、上一季末和上年同期末，只取该公司类型的关键资产、负债、减值和资本科目。
- `queryFinanceAudit`：至少核对最近一期应审计报告；出现非标意见、强调事项、持续经营重大不确定性、会计师变更或费用异常时回看历史。
- `queryFinanceMainbz`：适用时用于识别产品/行业/地区增长、利润贡献和结构变化。
- 公告正文与附注：按通用清单和公司类型策略提取会计政策、估计、减值、关联方、或有事项、受限资产、债务期限、分部、研发、后续事项等证据。

当初始证据暴露异常时再定向补取往期字段。不得为“数据更全”而无限扩展历史区间。

### 5. 先建判断，再写报告

为每个核心结论建立证据链：

`报表事实 → 财务数据/附注 → 会计与经营原因 → 持续性或风险 → 反方解释 → 财务判断 → 跟踪指标`

至少回答增长质量、利润质量、资产质量、现金创造、成本与研发、偿债与资金运用六条主线。优先保留会改变财务结论、报表可信度、偿债能力或流动性判断的重大事项，普通波动不为凑章节强行上升为亮点或风险。每发现一个正面财务证据，主动寻找最强的反向解释；每发现一个风险，也检查是否有抵消证据。区分：

- **事实**：公告原文、附注或接口数值直接支持；
- **推断**：由多项事实推导，必须写出逻辑；
- **未知**：资料不足，不能用行业常识补成公司事实。

### 6. 审计、附注和勾稽核验

附注不是补充阅读，而是风险分析的核心来源。总结中必须明确审计状态；非标意见、强调事项、持续经营重大不确定性及有实质影响的附注进入“风险排雷”，标准意见和无异常附注不另起重复章节。核对非经常损益、收入确认、减值、研发资本化、关联交易、担保诉讼、受限资产、债务约束和期后事项。关键审计事项本身不等于非标意见；季报通常未经审计，不能仅因无审计意见判为风险。

对利润表、资产负债表、现金流量表及指标做交叉核验。发现接口与公告、当期与比较期、利润与现金、增长与营运资本之间矛盾时，优先解释矛盾，不得挑选对结论有利的数字。
同一报告期、同一口径的数值冲突时，以最新完整官方修订报告为准，并在数据局限中记录接口差异；不能静默混用两个版本。

### 7. 输出与终检

严格按 [输出规范](references/output-template.md) 组织，第一章必须是判断性总结。只展示能支撑结论的数据，并同时给出报告期、单位和比较基准。

交付前逐项检查：

- 是否以最新完整官方定期报告为主分析期，并说明各财务接口与其是否同步；
- 是否误把累计数当单季度、误对资产负债表做差额或误对比率做差额；
- 是否读取附注并明确审计意见；
- 是否覆盖财务亮点、风险排雷、三项财务健康度、成本与研发、增长和跟踪指标；
- 是否有正反双方证据、核心报表变化、增长驱动、偿债能力和资金运用判断；
- 每个重大判断是否有可追溯证据，未知项是否明确留白；
- 亮点和风险是否只是结论索引，详细证据是否只在后续对应章节展开一次；
- 是否避免指标堆砌、伪精确阈值、重复数据和无证据的同行比较。
